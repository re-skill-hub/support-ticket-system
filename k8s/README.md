# Kubernetes manifests

These base manifests (`00`–`09`) were built and validated against **Docker Desktop's built-in single-node Kubernetes cluster**, not Azure Kubernetes Service (AKS). They're ordinary Deployments/Services with no Docker-Desktop-specific fields. `k8s/azure-dev/` is a **separate, hand-maintained manifest set** for a real AKS cluster (managed images via ACR, `ClusterIP` + ingress-nginx/cert-manager instead of `LoadBalancer`, Key-Vault-backed secrets, resource limits already set on every app Deployment) — despite the directory being called an "overlay," it does not use kustomize `bases:`/`patches:` to inherit from these files; it duplicates their shape by hand, so the two sets can drift and a change here doesn't automatically apply there. `09-api-gateway.yaml` (a YARP reverse proxy — see `docs/distributed-resilience.md`) has a matching Deployment/Service in `k8s/azure-dev/workloads.yaml` too — `client/nginx.conf` routes every `/api/*` call through it in both environments (and Docker Compose).

Each Service here exposes two named ports: `debug` (5101/5102/5103/5100, for hitting a service directly from the host — Docker Desktop's Kubernetes exposes `LoadBalancer` Services on `localhost` directly) and `internal` (8080, matching the container's own port). Only `internal` is what nginx/the gateway actually connect to from inside the cluster — a Service only listens on ports it declares, so before this was added, nothing inside the cluster could reach any backend through its Service at all (only Docker Compose and AKS, whose Services only ever used 8080, worked).

`sqlserver`, `rabbitmq`, and `mailpit` run as single-replica, no-backup pods purely so the stack is self-contained for a local demo. A production deployment would point at a managed Azure SQL Database and a managed message broker instead of running stateful infra in-cluster — see `docs/requirement/gap-analysis.md`. Note also that `00`–`09` have no resource requests/limits set on the app Deployments (only the infra pods do) — the `k8s/azure-dev` Deployments already set them; bringing the base manifests to parity is tracked as a deferred item in `docs/distributed-resilience.md`.

**Full deploy instructions (prerequisites, the kind-vs-kubeadm image-loading gotcha, deploy/tear-down steps) are in [`docs/running-the-app.md`](../docs/running-the-app.md#track-2-local--kubernetes-docker-desktop).**

For the AKS trial deployment specifically, see `k8s/azure-dev/README.md`, `docs/azure-deployment.md`, and `docs/ci-cd-pipeline.md`.
